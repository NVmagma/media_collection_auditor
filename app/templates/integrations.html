Library coverage

GET /api/v1/coverage reports folder counts, missing/invalid/future dates and records without a matching stage folder. Optional query: library=Movies or library=TV. Enable API Coverage under Settings → Integrations. It reads configured local folders only; no Jellyfin requests or media changes. Partial coverage returns 503 with unknown aggregate totals. A mismatch is a review finding, not proof that media was deleted.

Scan observations

GET /api/v1/scan-history supports page (default 1), page_size (1–20, default 5) and outcome (all, completed, review, unknown). Recent attempts are read from persistent JSON scan history. History survives application restarts.

GET /api/v1/proposals reports preview counts for the latest recorded attempt. It does not list titles or authorize actions. While a scan runs, the current status and prior recorded attempt are identified separately. Neither endpoint triggers a scan.

Backup status

GET /api/v1/backup-status verifies one explicitly selected logical backup packet. It checks the selected completion receipt and the tracking and saved-settings payload hashes. It does not find the newest backup, compare with current tracking, test restoration or authorize recovery.

Selection requires INTEGRATION_API_BACKUP_DIRECTORY (container path), INTEGRATION_API_BACKUP_IDENTITY (device:inode) and INTEGRATION_API_BACKUP_FINGERPRINT (reviewed receipt SHA-256). The packet must be reachable in the container through a reviewed private location. This page does not copy packets, change mounts or configure the selection.

Missing or failed verification returns 503. Older receipts without a capture timestamp report unknown age; file modification times are not used. A verified packet may still be old and may not match your current tracking.

Failure notifications

In Settings → Notifications, configure a destination and enable Notify on Operational Failures. Preview alerts also require Notify During Dry Runs. Apply Requested Settings to activate your reviewed values.

Scan failures send fixed, redacted messages. Repeated failures are suppressed per event/destination in the current process; failed delivery is not automatically retried. Relevant successful recovery or a process restart can rearm alerts. Delivery does not change scan results, tracking or recovery state.

Diagnose a connection

  • 401 Unauthorized: token missing or incorrect. A browser sign-in cannot replace Bearer authentication.
  • 404: check the path; title routes also return 404 when title details are disabled. Missing or invalid server token configuration disables the API.
  • 400: library must be exactly Movies or TV, with only one library query value.
  • 503: tracking or coordinator information is unavailable; this is not a healthy empty result.
  • External request failed: check the base URL, dashboard private-network access, connectivity and timeouts. This message alone cannot identify the cause.

Authenticated GET /api/v1/readiness lists supported routes and tracking readiness without collecting Jellyfin data. /health checks the web process only.

Replace the integration token

  1. Open Settings → Integrations. Generate or enter a private token, copy the new value privately, and Apply Requested Settings.
  2. Replace the Bearer credential in each Homarr/Homepage widget. The old token stops working immediately.

No container restart is required. Blank preserves the saved secret; Disable API revokes it. Never include tokens in URLs, screenshots, logs or support messages.
